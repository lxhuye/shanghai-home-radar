# 开源发布范围

本项目公开的是研究软件，不是上海二手房数据库，也不是已经通过实盘校准的服务。

## 发布方式

从当前工作树创建白名单源码快照，使用新的 Git 历史。原工作树、未提交变更、模型参数、私有数据和已有研究历史保持不动。不要将本地 `.git` 或已有私有仓库直接改为公开。

使用 `scripts/export_open_source.py --output <全新目录>` 生成独立副本和旁置 SHA-256 文件清单，
然后人工审查、扫描。脚本不联网、不创建 GitHub 仓库、不自动授予许可证或证明所有内容可公开。
本次已运行的检查与未验证项见 [源码快照验证记录](OPEN_SOURCE_CHECKS.md)。

可发布范围包括源码、迁移、依赖清单、非秘密配置、文档、合成 fixtures 与测试。包内第三方依赖继续使用各自许可证；不将其二进制或源码副本打包进本仓库。

## 必须排除

- `.env` 及个人环境配置；保留无真实凭据的 `.env.example`。
- `data/raw/`、`data/inbox/`、`data/exports/`、`data/local_browser/`、数据库和备份。
- Cookie、登录态、浏览器 profile、会话文件、DOM/截图和实际网页导出。
- 真实房源池、成交记录、买方偏好、人工盲标与冻结运行。
- `data/evidence/sample/` 下的本机研究证据和地理编码/第三方数据缓存；公开代码缺少这些文件时应报告证据不足。
- 阶段验收报告及私有研究笔记；它们不是公开版本的测试承诺。
- `.git` 历史、个人对话、绝对用户路径、构建缓存、依赖目录和同步冲突副本。

测试不得隐式依赖被排除的真实资料。用单独的合成 fixture 或测试中构造的输入验证数据契约；这种 fixture 不得出现在运行时 SAMPLE 证据目录中。

## 发布前验收

1. 维护者确认仓库、可公开范围与许可证。
2. 审查白名单文件清单；不使用 `git add .` 上传原工作目录。
3. 对快照和首次提交做脱敏密钥扫描，并检查数据文件、绝对路径、个人信息及大文件。
4. 从不含原始数据和本机缓存的干净快照执行测试、类型检查、格式检查及文档链接检查。
5. 记录通过、失败和跳过项；不把本地历史测试数量当作当前 CI 结果。
6. 公开后核对仓库可见性、文件清单和 README。不得为开源而更改冻结校准数据或模型阈值。

## 已知边界

扫描无告警不等于安全保证。当前依赖范围不完全锁定；基础镜像、操作系统和新版本依赖需要持续维护。许可证适用于维护者有权许可的项目内容，不转授房源网站、地图、统计材料或合作方数据的权利。
