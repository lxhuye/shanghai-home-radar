# 精准推荐实施记录

用户于 2026-09-08 批准按购房条件、真实证据、可核查理由、独立验证四步推进。

## 已实现的工作台

打开本机 `http://127.0.0.1:5057/`。

- 购房条件：保存区域、预算、卧室、电梯、楼层和通勤。初始徐汇250–300万仅是现有来源的范围，默认未确认。通勤可以明确不限制，否则需要目的地和时间。未知必要条件不会通过匹配。修改条件不扩大采集范围。
- 逐套证据：保存来源链接、证据时间、核验人和原值。可录入电梯、楼龄、户型、楼层、产权类型、实际通勤、卖方报价。卖方报价不改写挂牌价，也不冒充可执行成交价。
- 成交证据：批量导入人工核验的已成交记录，进入现有P4可比选择与P3成交参考分布；不是仅展示附件。记录不合格、时间不合格、同编号冲突会拒绝整批。重复导入不新增记录。
- 未来证据：使用现有验证器接收带公开来源的因子、项目与就业中心资料。就业中心需要实际就业观测依据和已核验坐标。地区人口和存量代理仍保留原说明，不能当实测买家或供给。
- 流动性证据：接收供应方声明完整覆盖的30天市场汇总，调用现有流动性引擎；未知数不置零，超过36小时的窗口不作为当前证据，单页来源仍保持partial。
- 独立复核：从真实观测去重后抽50套，抽样不依据模型排名。复核页先只显示事实和冻结的购房条件。全部标注后冻结，再显式展示模型。展示后另做理由复核；原始标签不能更改。
- 验证资格：首次独立批次全部指标通过后仍需新房源复测。后续50套必须在首次完成后新观测、无房源重叠、同模型/条件/来源范围，并通过原阈值，才能形成范围内研究验证资格。条件、模型或范围变化会使资格不匹配。不会因此解锁原P5.7五区域生产门槛。

## 接入接口

写请求只接受本机同源操作，要求 `x-handoff-action: 1`。

| 用途 | 接口 |
|---|---|
| 条件 | GET/PUT `/buyer-profile` |
| 条件匹配和验证状态 | GET `/recommendations` |
| 单套人工核验证据 | GET/POST `/property-evidence` |
| 成交空模板/完整结构 | GET `/transactions/template`、`/transactions/schema` |
| 成交导入 | POST `/transactions/import` |
| 流动性空模板/导入 | GET `/market-evidence/template`、POST `/market-evidence/import` |
| 因子空模板/导入 | GET `/future-evidence/template`、POST `/future-evidence/import` |
| 复核批次 | GET/POST `/validation-runs` |
| 标注、冻结、展示、理由复核 | POST `/validation-runs/{id}/labels`、`/freeze`、`/reveal`、`/reviews` |

成交每条至少需要 `record_kind=closed_transaction`、`source_record_id`、区/板块/小区、面积、成交总价（万元）、卧室数、`sold_at`、`source_url`、`observed_at`、`verified_by`。来源须为无凭据的HTTPS链接。时间包含时区，成交不能晚于证据观测。批次的 `source_id` 标识资料提供方，`data_mode=sample` 标识本地研究用途。

空模板不提供可误用的虚构成交。字段完整不等于平台已确认真实性；这里记录的是核验人对来源的复核声明。

## 时间与隔离

原始挂牌观测与价格保持不变。补录资料使 `evidence_cutoff_at` 前进，`observed_at` 仍是来源真实观测时间，旧挂牌不会因为补证而变新。派生报告缓存包含补充证据内容。

条件、追加证据与复核批次位于 `data/exports/browser_handoff/recommendation/`。来源抓取不因填表或导入触发。该工作台不向中介发消息，不修改旧校准池或生产数据库。

## 尚未完成的真实验收

实现入口与通过代码测试不等于房源数据已补齐。目前尚无真实成交、实际就业或完整流动性资料通过这些新入口导入，也没有替任何人填写复核标签。还需确认个人约束、接收并核验真实资料、完成独立50套复核和新房源复测。资料缺失时继续显示具体缺口，不调低评分门槛或生成模拟推荐。
